# 短剧 AI 制作流程

把一份短剧剧本制作成连续、可追溯的 AI 视频。以《雾锁黑石》的实践为参考，但每次都从新故事的素材、风格、时长和生成模式出发，不沿用旧故事的角色、场景、道具、提示词或参数。

## 适用范围

- 将剧本拆成逐镜头视频，并保持人物、道具、空间和时间连续。
- 使用 MiniMax-H3 或其他视频模型生成镜头；使用本地提示词优化模型时，也要保留用户原始要求和媒体引用语义。
- 将独立镜头剪成正片，按需要制作片头、片尾、配乐、歌词字幕和多比例封面。
- 用户只要求其中一项时，只执行该项及其必要的前置检查，不默认扩展为全片制作。

## 关键原则

1. **先锁定故事事实，再写生成提示词。** 角色、事件、时间、空间、台词和镜头边界以用户提供的剧本为准。未经用户要求，不改台词，不新增剧情。
2. **一镜一份生成描述。** 镜头时长、画面动作、机位、声音和角色必须落在该镜头自身；转场是剪辑元数据，不能被模型误当成镜头内部动作。
3. **引用媒体要有明确用途。** 每张图、每段视频和每段音频都要说明是人物/场景/道具设计参考、动作参考、首帧/尾帧，还是原音复用。不能把静态图片伪装成视频或音频引用，也不能在 T2V 中误带素材。
4. **空间连续性先于单张资产的漂亮程度。** 场景入口、出口、方向、楼层、路线、道具携带状态应先在关系图或连续性表中确定，再生成资产和分镜。
5. **可追溯、可恢复。** 保存原始剧本、结构化镜头表、资产映射、用户原始提示词、优化后提示词、工作流、模型/参数、任务状态和输出文件清单。失败镜头可单独重跑。
6. **不把提示词相似误称为声纹锁定。** 固定 speaker ID 和一致的音色描述可以提高相似度；只有模型的说话人参考/声音克隆能力及明确的音频参考输入才可能提供更强的身份约束。不同 seed 不等于同一声纹。
7. **真实检查成片。** 文件存在不等于镜头合格。逐镜检查画面、动作、引用、声音、时长、分辨率和切点；发现错误应修正源提示词/资产/工作流并重生成。

## 阶段 0：建项目并盘点输入

建立独立项目目录，例如：

```text
项目名/
  剧本/
  设定/                 # 世界观、人物、空间关系
  资产/                 # 人物、场景、道具、怪物等
  分镜/                 # 结构化镜头表、逐镜提示词
  工作流/               # 原始与本项目工作流副本
  分镜视频/             # 逐镜输出、缩略图、生成清单
  音乐/
  片头/
  片尾/
  封面/
  成片/
  报告/
```

开始前记录：

- 剧本版本、目标片长、画幅、帧率、受众和目标平台。
- 用户指定的必保内容：台词、歌词、字幕、人物关系、关键动作、结局、不得出现的镜头。
- 可用模型、ComfyUI 工作流、GPU/显存、资产生成工具和后期工具。
- 输入媒体清单及各自用途；检查路径可访问、视频可解码、音频可播放。

不要假设当前机器和《雾锁黑石》制作环境相同。模型文件名、分辨率、步数、分段长度、提示词模型、URL 都需要按当前环境核对。

本 skill 自带可复用工作流模板，见 [`workflows/`](workflows/)：

- [`minimax_h3_multimode_api.json`](workflows/minimax_h3_multimode_api.json)：MiniMax-H3 多模式 API 工作流模板，保留 T2V、I2V、首尾帧和 Ref2V 模式选择、媒体输入、提示词优化开关、逐步采样预览与视频保存节点。模板内图片/视频/音频槽位已清空，提示词和输出前缀已泛化。
- [`yue2_music_api_example.json`](workflows/yue2_music_api_example.json)：可选 YuE2 歌曲生成 API 工作流示例，歌词与风格字段是待填写占位内容。

YuE2 的画布工作流和安装说明另见 [`AI-Drama/YuE2/README.md`](../../YuE2/README.md)，其中包含文生音乐与音乐翻唱 UI 工作流、ModelScope 模型下载和 ComfyUI 安装检查。

这两份是 ComfyUI **API 格式**工作流，不是可直接在画布中编辑的 UI 工作流。使用前导入/提交到兼容的 ComfyUI API，检查所需自定义节点已安装，再按当前机器选择模型文件、文字编码器、VAE、LoRA、采样参数和输出目录。模板不包含模型权重，也不保证其他 ComfyUI 版本或节点版本完全兼容。运行前核对节点类型是否存在，并确认工作流里没有旧故事的媒体路径、提示词、音频或输出前缀。

## 阶段 1：剧本结构化与拆镜

1. 阅读完整剧本并提取人物表、地点表、时间线、关键道具、剧情因果、视听母题和结尾状态。
2. 将剧本拆成镜头记录。每条至少包含：

```json
{
  "shot": 1,
  "scene": "场景标识",
  "start": "00:00",
  "end": "00:06",
  "duration": 6,
  "shot_size": "中景",
  "visual_description": "镜头内可见内容与动作",
  "camera": "机位与运动",
  "dialogue": [{"speaker": "角色名", "text": "原台词"}],
  "sound": "环境声与拟音",
  "music": "配乐要求或无",
  "transition_to_next": "剪辑转场及依据",
  "asset_ids": []
}
```

3. 镜头时长总和要与目标片长一致。检查起止时间无空隙、无意外重叠；依据动作复杂度和模型单次时长限制拆分长镜头。
4. 每个镜头结尾写转场建议及其理由。默认硬切；只有叙事需要时才使用声桥、动作匹配、视线匹配、叠化等。转场发生在当前镜头末帧之后，除非剧本明确要求镜头内转场。
5. 对照原剧本逐字校验所有台词、歌词和必须出现的屏幕文字。为每个镜头保留原始描述，不以优化提示词覆盖源文本。
6. 动作镜头检查动作准备、发力、接触/结果、角色位移与镜头方向；文戏按需要安排反应镜头或空镜；不要为满足“电影感”而任意加镜头。

## 阶段 2：空间与连续性设计

制作一份空间关系图或表格，明确：地点之间如何到达、入口/出口、房间相对方位、楼层/高差、角色行动方向、摄影机轴线。对同一地点的镜头使用统一命名和同一组空间资产。

逐镜做连续性表：

| 项目 | 检查点 |
|---|---|
| 人物 | 服装、发型、伤势、情绪、所在位置、朝向、手上物件 |
| 道具 | 由谁持有、是否打开/损坏/遗失、出现在画面的哪一侧 |
| 空间 | 入口出口、屏幕方向、视线轴线、光源方向、天气与时间 |
| 事件 | 上一镜动作结果是否延续；不得在后续镜头无原因复原 |
| 音频 | 环境底噪、角色声音、音乐是否延续或有意改变 |

新镜头只能改变连续性状态时，剧本必须提供原因或剪辑表达；否则修订分镜或提示词。

## 阶段 3：规划与生成资产

先列出资产需求和使用镜头，再批量生成/制作。至少考虑：

- **人物资产**：角色肖像、服装/体型参考、表情和可识别特征。需要无脸三视图或四视图时，在生成说明中明确：肖像区域提供身份参考，转面图只表示身体/服装比例，不显示脸部五官。
- **场景资产**：建立空间全貌、固定结构、出入口和方向；同一地点跨镜头复用对应场景资产。
- **道具资产**：提供独立、清晰、可识别的外观；标出重要颜色/标志/携带关系。
- **生物/特殊角色**：以轮廓、结构、材质和关键特征区别于普通人；多视图保持同一设计。

资产提示词避免把人物设定板、说明文字、背景杂物误作为成片元素。需要透明背景时明确要求透明底；场景需要单独资产时不要把角色烘焙进背景。检查生成图的分辨率、文字、脸、视图数量和跨资产一致性。用户提供的资产不得在没有授权的情况下覆盖或重绘。

为每项资产分配稳定 ID，例如 `CHAR_A`、`LOC_01`、`PROP_03`，建立 `资产索引.md`：文件名、版本、用途、空间关系、使用镜头、来源及是否为用户提供。

## 阶段 4：为镜头分配媒体引用

将镜头表关联到资产 ID，并输出每镜的媒体清单。区分模型生成模式：

- **T2V**：纯文本生成；清空图片、视频和音频引用槽，避免残留上次任务素材。
- **I2V**：图片作为首帧/起始条件，说明从该帧如何延展。
- **首尾帧模式**：分别指定首帧与尾帧，描述两者间连续可行的运动路径。
- **Ref2V/多参考**：逐一说明图、视频、音频的角色和时间用途；引用标签严格对应实际输入顺序。
- **动作参考视频**：明确视频提供动作/节奏参考；它是否复用原画面或原音，必须单独写清楚。
- **音频参考**：明确是复用原音、声音风格参考还是转写内容；没有真实音频输入时不可写成 `<Audio N>`。

对每次提交都构建全新的输入列表，而不是沿用旧工作流残留。每个媒体槽位要么有真实、可读取的文件，要么为空。记录最终文件名、服务端上传名、序号、模式和用途；排查错素材时以实际提交 payload/工作流 JSON 为准，不能只看 UI 标签。

## 阶段 5：提示词优化与校验

使用适合当前 H3 模式的官方/本地写作规范。对于 MiniMax-H3 Ref2VA，使用六段顺序：

1. `subject_definitions`
2. `summary`
3. `retention_analysis`
4. `detailed_description`
5. `overall_soundscape`
6. `non_diegetic_music`

通用要求：

- 将**用户原始提示词**和**优化后提示词**分别保存并在报告中并列记录。
- 台词、歌词、引用内容和规定的画面文字逐字保留；标明说话人。
- **把说话角色写进 `subject_definitions`，作为跨镜头的声音身份锚点。** 为每位说话角色分配全片固定的 `Subject` 编号和 speaker ID，并在每条相关镜头提示词中重复同一组编号、身份和音色描述；台词段落也使用同一 speaker ID。不要因为换场景或换镜头就重新编号或改写其声线。例如：

  ```text
  <Subject 1> is Lin Mo (S1), the same young adult male speaker throughout the film. His voice is low-mid pitched, slightly breathless, anxious, and restrained, with a consistent Mandarin accent and speaking pace.
  ```

  这类写法为模型提供稳定的角色/声音条件，实际项目中观察到能帮助跨镜头保持相近的音色。每次都尽量复用同一段声线描述，避免只写“同一个人”或每镜换一套形容词。它属于提示词层面的软一致性，不是声纹提取或硬锁定；不同 seed 不会自动统一声纹。若用户要求严格复现同一说话人，先确认模型/工作流是否支持并实际接入同一说话人参考音频或声音克隆，再如实说明能力边界。
- 只使用实际提供的 `<Picture N>`、`<Video N>`、`<Audio N>` 标签。引用标签编号与媒体槽位一一对应，不能臆造引用。
- 指出每个引用的用途及保留强度：身份/外观、空间布局、道具、动作、首尾帧或原音复用。不能将设计参考错误写为精确首帧/尾帧。
- 只描述当前镜头。转场备注放在镜头元数据，不写进生成画面、当前镜头音轨或生成提示词；不预演下一镜。
- 写可观察的动作、构图、机位、环境和光线，少用含糊抽象形容词；避免互相冲突的身体朝向和视觉指令。
- 若出现模型常见的关键词污染、错误道具联想或空间歧义，使用防污染规则改写成直接可见的画面描述。

采样前自动检查：六段齐全且顺序正确；所有引用存在并编号正确；无幽灵媒体；时长一致；对话原文一致；没有跨镜头事件；动作与首尾帧条件兼容；没有把编辑转场写成镜头内动作；输出 token 达到限制时明确报错或重试，禁止静默截断。

## 阶段 6：生成、恢复与记录

1. 先选有代表性的测试镜头（近景脸、复杂动作、多人、场景空镜各一类），验证模型、参考输入、音频和分辨率，再批量提交。
2. 先复制工作流到项目目录并确认节点模式、模型、文本编码器、VAE、LoRA、分辨率、帧率、时长、步数、seed、音频、输出目录。
3. 分批逐镜生成，避免一次性排队造成显存/队列压力。长任务每完成一镜就保存 manifest，包含 prompt ID、状态、错误、源 prompt、优化 prompt、输入资产、模型/版本、参数、路径、实际时长和实际宽高。
4. 失败后根据日志定位节点和原因。调整单一必要变量并重试；保留失败记录和旧输出，不覆盖已通过版本。
5. 实际检查视频元数据。用 `ffprobe` 验证尺寸、帧率、时长、音频流和编码；生成器请求的尺寸不等于实际导出尺寸。
6. 种子用于复现或控制某次生成的随机起点。跨镜头可使用不同 seed；固定 seed 不保证人物身份、画面或声音一致。

## 阶段 7：逐镜质检与正片剪辑

逐镜播放或抽帧检查：

- 角色身份、人数、服装、脸部、手脚和身体结构。
- 动作是否符合源分镜与动作参考；不存在无故变背景、换人、重置道具或跳动作。
- 场景结构、方位、屏幕方向、空间路线和光线是否连续。
- 引用资产是否实际生效且用途正确；文生视频是否夹带旧参考。
- 台词/歌词是否完整准确，音画是否同步，环境声是否合理。
- 片段有无黑帧、闪帧、叠影、首尾帧异常、音频爆音或时长多出。

输出问题清单并按优先级修复：剧情/引用错误 → 连续性/动作错误 → 人物结构/脸 → 音画与时长 → 细节与调色。只重生成受影响镜头，回归检查相邻镜头与转场。

剪辑时按时间线组装，保持统一画幅、帧率、色彩与音频采样率；先确认镜头顺序和剔除清单，再做转场、音频桥接、调色和编码。不要以拼接成功代替观看最终成片。

## 阶段 8：片头、音乐、片尾与封面

按用户需求选择制作内容：

- **片头**：优先从正片已通过质检的镜头中挑选有吸引力的短段；片名出现前有明确节奏；片头结束后自然接正片开场。
- **主题曲**：先依据故事主题、人物弧光和结局写歌词并让用户确认歌词；用户规定不得修改的歌词逐字锁定。生成音乐时记录模型、工作流、风格描述、时长、seed 和实际文件。
- **片尾歌词**：依歌曲实际时长决定滚动时长；确保最后一句歌词完整显示，音乐不被截断；片尾背景可以延续正片末帧，正片声音与歌曲做适当淡入淡出。
- **封面**：分别按横屏/竖屏构图；先生成无字图，再排标题，避免模型生成错字。检查字体授权、标题可读性和安全边距。

片头/片尾剪辑脚本应把项目路径、镜头编号、剔除镜头、字幕、字体和成片名配置化。脚本可重跑，且不修改源镜头。合并后检查片长、尺寸、音频、首尾和标题。

## 阶段 9：交付报告

制作一份简明但可复现的报告，至少包含：

- 项目片长、镜头数量、最终规格和交付文件。
- 各场景所用模型、版本、工作流、文本模型及核心参数。
- 每个镜头的源分镜、输入资产、用户原始 prompt、优化后 prompt、实际输出路径、时长/尺寸、状态和转场。
- 哪些镜头被剔除或重做及原因；用户提供资产的来源说明。
- 音乐/片头/片尾/封面使用的模型、素材与脚本。
- 已知限制或仍待处理的问题。

报告要链接到资产索引、分镜表、生成清单和实际成片，避免只写“已完成”。

## 推荐目录与交付清单

```text
剧本/                 原始剧本与锁定版本
设定/                 人物、场景、空间关系、连续性表
资产/                 资产文件与资产索引
分镜/                 结构化分镜表、源提示词、优化提示词、校验结果
工作流/               按故事复制并配置的工作流
分镜视频/             逐镜视频、缩略图、生成清单/manifest
音乐/ 片头/ 片尾/ 封面/
成片/                 最终导出
报告/                 制作报告与复现说明
```
