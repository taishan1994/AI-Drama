# 总体目标

对聊斋志异的所有故事以**上美影二维动画风格**的短片进行重制。参考喷水、瞳中人。

# 一般流程

1. 先从《聊斋志异》【爱上阅读_www.isyd.net】.txt找到对应故事的文言文，然后翻译成白话文，接着将其改编成剧本，一个吸引人的剧本是这样的：

   ```
   # 吸引人剧本的核心要求
   
   ## 1. 钩子：开篇必须快速抓住注意力（最重要）
   
   前 30 秒 / 第一页就要抛出冲突、悬念、反差或者痛点，不能慢悠悠铺垫。
   可选钩子类型：
   
   - 悬念：抛出一个未解问题「他明明赢了，为什么连夜删掉全部代码？」
   - 反差：打破固有认知「大家都觉得简单的滑动窗口注意力，其实藏着重复计算陷阱」
   - 危机：角色立刻面临选择、损失、压力
   
   > 
   > 反面：大段背景介绍、冗长设定，观众直接划走。
   
   ## 2. 清晰目标 + 障碍（核心骨架）
   
   主角要有**明确想要的东西**，同时持续有阻碍，不能一路顺风顺水。
   公式：主角目标 → 遇到障碍 → 尝试解决 → 新麻烦出现。
   没有障碍 = 没有戏剧张力，观众看不下去。
   
   ## 3. 人物：有动机，有弱点，能共情
   
   不用复杂人设，但人物要有**内在动机**：为什么他一定要做这件事？
   最好带一点弱点 / 矛盾：比如想刷 GitHub 徽章，但又不想写水 PR；想拿到 committer，但害怕维护项目。
   观众会共情 “人物的挣扎”，而不是单纯看信息科普。
   
   ## 4. 持续的冲突与反转
   
   冲突不只是吵架，分几种：
   
   - 外部冲突：遇到难题、对手、客观限制（项目没人回复、PR 一直被拒）
   - 内部冲突：纠结、自我怀疑、取舍（要不要提交水 PR 换徽章）
   反转不用惊天动地，**预期违背**就行：以为很容易拿的会长，其实背后是责任不是头衔。
   
   ## 5. 节奏：张弛有度，信息分层
   
   - 紧：冲突、悬念、高潮（抛出问题、遇到挫折）
   - 松：解释、补充信息、情绪缓冲
   不要全程高密度输出，也不要全程平铺闲聊。每一小段结尾留小钩子，引导继续看下去。
   
   ## 6. 明确主题 / 落点（看完能记住）
   
   剧本结尾要有核心观点，不是单纯讲一个故事。
   例：刷 GitHub 徽章和 committer，不是为了简历装饰，是持续贡献的副产品。
   观众看完能带走一句话，记忆点更强。
   
   ## 7. 台词简洁，符合人设
   
   台词不说书面长句，口语化；每一句要么推进剧情，要么暴露人物，**没有废话**。
   科普类剧本：把专业概念包装在人物行动里，不要大段独白讲课。
   
   ## 8. 情绪闭环
   
   从开篇情绪（好奇、疑惑）→ 中间起伏（受挫、顿悟）→ 结尾收束（感慨、启发）。
   哪怕是短视频短剧本，也要完成一轮情绪起伏。
   ```

   你可以酌情参考。

2. 然后基于剧本参考minimax-h3的使用手册以及h3-prompt-writing skill，帮我设计分镜。每一个分镜需要说明主要的人物、环境。

3. 接着基于分镜，分析出里面所需要的角色、环境、道具和特效，帮我设计文生图片的prompt，以方便我生成资产，资产包括：角色设定板、道具设定板、环境设定板、特效与道具设定板。其中，角色设定板图片分四个部分，最左边是人物主体头像，右边分别是正面、侧面、背面三视图。其余资产你自行决定。

4. 有了资产之后，结合confyui+minimax-h3的使用，帮我设计文生视频的prompt，每一个分镜需要说明引用的资产。生成视频可以有全能参考生成和基于首尾帧来生成，你可以自行决定。

# 视频生成标准

1. 视频必须严格按照要求来生成，必须保持角色的一致性、声纹的一致性和环境的一致性。
2. 除了prompt里面说明的旁白或者对白外，不能有额外的人声，
3. 生成的视频必须和当前的风格相匹配。
4. 不要有额外的字幕。
5. 生成的视频前后之间要有逻辑性，必要时可以生成关键帧参考进行视频的生成。

# 视频验收标准

每一段视频生成完之后要做以下验收：

1. 是否有额外的人声。
2. 视频是否出现了字幕。
3. 视频是否按照prompt的要求进行了生成。
4. 视屏中的角色和声音是否是一致的。
5. 验收通过的视频要粗知道

# 视频后处理

1. 生成一段前置视频，说明：改编自 《聊斋志异》\n故事名\n作者：西西嘛呦
2. 将每一段视频拼接起来，要注意不同段视频之间的平滑过渡，你可以适当剪辑和优化。
3. 对每一个角色第一次出现的时候，需要在其附近为其标注人名，人名采用竖着的方式，注意也要是上美影风格的字体。
4. 解析出声音对应的字幕，添加到视频中，字体大小要始终，采用白色字体。使用whisper/large-v3-turbo 进行语音识别。
5. 生成抖音需要的横屏和竖屏的封面，封面上要出现故事名，同时字体要有上美影特点，不是简单的宋体。

# 其它经验

## 1. 人物一致性

- 每个有名字的人物建立唯一角色设定板：正面头像、全身、三视图、服装颜色、发型、年龄、体态和不可变特征。
- 每个角色首次出场用角色设定板生成；通过验收的尾帧作为下一镜首帧。近景、转身、奔跑不能重新纯文生一个新脸。
- 同一角色在不同镜头中必须保持衣着、发式、身高比例和年龄感。尸变中的女尸、车夫甲和老翁尤其不能被模型互换；喷水中的阿绣、阿莲和仆人必须按空间位置辨认。
- 每个镜头生成前写“人物清单+站位+朝向+动作状态”，生成后逐帧确认人数、身份和朝向。

## 3. 场景与空间连续性

- 每个场景建立主空间图，固定门、窗、床榻、桌案、供桌、井、树等永久锚点。
- 镜头只能改变机位和景别，不得无提示移动建筑和家具。上一个镜头尾帧是下一镜首帧的最高优先级；跨场景必须有明确过渡镜头。
- 生成前写清楚“谁从哪里进入、移动到哪里、谁面对谁、谁不能出现”。这能避免尸变中老翁从屋内凭空出来、女尸从错误门口出现、车夫少人或多脚等问题。
- 首尾帧重点检查：人物数量、脚是否与身体相连、门窗方向、家具位置、尸体头部朝向、道具数量和最后动作是否完成。

## 4. 声音与对白

- 声音分为对白、环境声、音乐三层。无对白镜头明确禁止旁白、其他人声、动物叫声和音乐；有对白镜头也只能出现剧本规定的人声。
- 每个角色先保存一条干净声纹锚点，后续只引用同一锚点；禁止每个镜头随机生成新音色。对白生成长度应覆盖从第一字到最后一字，前后不要留无意义的人声。
- 环境声必须与画面匹配：雨夜有连续雨声，室内有低幅环境底噪；环境声不能盖住对白。Minimax-H3参考音频用于声纹时，必须确认它没有把原对白和噪声一起复制进新镜头。
- 生成后先听音频，再做语音识别。发现额外人声、狗叫、含混杂音、对白缺字或角色声纹漂移，先修音轨或重生镜头，不用剪辑掩盖。

## 5. 字幕与人名

- 必须先合成无字幕底片，再用整片音轨做 ASR；将识别结果与剧本逐句校正，按实际说话区间生成字幕，避免只按预设时间导致漏句。
- 对 ASR 的幻听要按镜头边界清理，尤其是无对白镜头和切镜头处的长段落。
- 字幕采用纯白、黑色描边、适度阴影；长句主动换行，不能超出画面。字幕文字必须与最终声音逐字一致。
- 人名只在该人物第一次出现时显示一次，持续约 1.5–2.5 秒；标签贴近人物头部或身体侧方，不要固定在画面边缘。
- 人名必须竖排、加粗、带半透明深色底框，避免细字和背景混在一起。标签位置按每个镜头实际人物位置单独设定。

## 6. 生成和验收流程

1. 剧本锁定：人物、对白、声音归属、动作因果明确。
2. 资产锁定：角色板、主空间图、道具图、首尾帧齐全。
3. 镜头卡：写起始状态、动作顺序、结束状态、声音层和禁止项。
4. 视频生成：只使用最后两张 GPU；需要时使用 SageAttention 加速，但加速不能改变步骤和质量。
5. 单镜头验收：抽取开头、中段、结尾帧；查看人数、空间、动作、角色脸和道具；单独听对白和环境声。
6. ASR 核对：镜头通过后再合成无字幕底片，识别对白并校正字幕。
7. 总片验收：检查切镜头首尾、对白和口型、字幕时机、首次人名、黑帧、音量和编码。

## 7. 已遇到问题与对应修复

| 问题                         | 原因                                     | 修复方法                                     |
| ---------------------------- | ---------------------------------------- | -------------------------------------------- |
| 人物变脸、年龄变化           | 每镜重新生成脸，未使用尾帧/角色板        | 固定角色板，尾帧接首帧，先验收资产           |
| 人数少、多脚、人物身份混淆   | Prompt只写“几个人”，没有编号和站位       | 人物甲乙丙清单，写清位置、朝向和不可出现对象 |
| 家具、门、床漂移             | 没有主空间图，镜头间只参考文本           | 主空间图+前镜尾帧双参考                      |
| 额外人声、狗叫、杂音         | 视频模型自行补全声音，参考音频夹带原对白 | 对白/环境声分层，短对白视频，ASR和听音双检   |
| 字幕缺失、错字、不同步       | 手写固定时间轴，没有先识别最终音轨       | 先合成底片，再ASR，按镜头边界校正            |
| 人名太细、离人物远、重复出现 | 全局固定位置和普通字重                   | 首次出现一次，贴头部，竖排加粗底框           |
| 画面逻辑跳变                 | 没有定义起始/结束动作                    | 每镜写状态机：开始状态→动作链→结束状态       |

## 8. 声纹的一致性

可以使用Fish-Speech进行声纹的克隆和锚定。minimax-h3可能会为某个角色生成第一次声音，后续需要保证和该角色声纹的一致性。
